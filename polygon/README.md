# Pine Polygon — проверка индикаторов и превью модели

Открывается **двойным кликом по `index.html`** — ни сервера, ни сборки.

## Что он делает и чего не делает

**Не делает:** не исполняет Pine Script. Pine компилируется на серверах
TradingView; ни виджет, ни Charting Library не принимают произвольный Pine.
Параметр `studies` в виджете принимает только встроенные исследования
(`"STD;MACD"`), ваш скрипт туда не подставить.

**Делает три вещи:**

| Панель | Что даёт |
|---|---|
| **Код и линтер** | Проверяет **синтаксис** локально и ловит ошибки разбора **до** вставки в TradingView |
| **Рынок** | Живой график TradingView встроенным виджетом — для контекста |
| **Превью модели** | Рисует то, что индикатор **должен** показать |

## Зачем нужен линтер

Компилятор TradingView отдаёт код ошибки и иногда номер строки, но не
говорит, что именно не так. Две самые частые ошибки:

```
CE10016  Extra closing parenthesis
CE10017  Missing enclosing character in the literal string
```

Обе синтаксические и обе ловятся локально. Хуже того, они часто **приходят
от одной причины**: разорванное переносом строковое выражение.

```pine
// так компилятор сломается
tooltip="Первая часть текста. " +
     "вторая часть."
```

Pine читает перенесённый литерал как незакрытый (CE10017), а весь код после
него — как содержимое строки. Поэтому какая-нибудь закрывающая скобка
оказывается «лишней» (CE10016). В этом проекте ошибка указывала на строку 64,
а искали её в скобках — и не находили.

**Лечение:** всё выражение на одной строке. Длинные строки Pine принимает.

## Превью — это эталон, а не приближение

Рисует не Pine, а **проверенная Python-модель** (`src/alpha_lab/`), выгруженная
скриптом `scripts/export_preview.py`. Модель — эталон: Pine-порт сверен с ней
**побитово** (`scripts/verify_pine_port.py`). Значит расхождение картинки с
индикатором в TradingView — дефект индикатора, а не превью.

## Почему в таблице стопы всегда −1R, а тейки +3R

Это не совпадение, а проверка геометрии: риск = `slAtr × ATR` на баре входа,
стоп на расстоянии 1R, тейк на 3R. Если в таблице появятся другие числа —
модель или её порт сломались.

## Обновление данных

```bash
# Данные превью (реальная история Binance)
uv run python scripts/export_preview.py --symbol BTCUSDT --timeframe 1h --bars 1200

# Исходник индикатора внутрь полигона
uv run python scripts/export_pine_source.py

# Самопроверка линтера (11 проверок)
node polygon/test-lint.js
```

## Файлы

| Файл | Что внутри |
|---|---|
| `lint.js` | Линтер: правила разбора Pine |
| `test-lint.js` | Самопроверка линтера — ловит ли он реальные ошибки |
| `chart.js` | Отрисовка превью: свечи, полосы, сделки, z-скор |
| `app.js` | Связка: редактор, линтер, виджет TradingView, превью |
| `preview.js` | Данные модели (генерируется) |
| `pine-source.js` | Исходник индикатора (генерируется) |

## Ограничения

- Линтер проверяет **синтаксис**, а не семантику. Типы, версии функций и
  области видимости по-прежнему проверит компилятор.
- Панель «Рынок» требует доступа в сеть. Без него покажется ссылка на
  TradingView.
- Данные превью — снимок на момент запуска экспортёра, не поток.
