# Alpha Lab — инструкция для работы с проектом

Этот файл читается автоматически в начале сессии. Здесь всё, что нужно знать,
чтобы продолжить исследование и не наступить на уже пройденные грабли.

---

## 1. Что это за проект

Исследовательский полигон для проверки торговых гипотез на криптовалютных
данных Binance USDT-M. Его ценность — **не в генерации идей, а в честной
отбраковке**: отличить закономерность от совпадения.

Проект сознательно устроен так, что большинство гипотез убивается. Это
нормальный режим работы, а не поломка.

**Язык:** комментарии, docstring и документация — на русском. Идентификаторы
в коде — английские.

---

## 2. Главное правило

> **Никогда не подбирай параметры по результату.**

Измерено, а не постулировано: перебор 475 конфигураций mean-reversion с
отбором лучшего по обучающему периоду дал лучший **train Sharpe +0.01** и
отрицательный результат вне выборки. Пространство было пустым, и перебор это
не меняет.

Если гипотеза не проходит гейты — правильный вывод «гипотеза мертва», а не
«попробуем другие параметры». Каждая новая попытка **повышает планку**: DSR
штрафует за число попыток как `√(2·ln N)`. Перебор не помогает по построению.

**Что делать вместо подкрутки:** проверить **другой класс гипотез** (см. §9).

## 7. Как добавить много данных

Озеро держит 1m-бары; из них ресемплятся все таймфреймы.

### Добавить символы

Правьте `configs/universe.yaml` — список `symbols`. Правила:
- только перпетуалы, торгующиеся ≥ 2 лет;
- **делистингованные пары оставлять в списке** — иначе ошибка выживаемости;
- смена состава меняет `experiment_id` (это правильно).

### Добавить период

`configs/universe.yaml`, поля `start` / `end`. `end: null` = по сегодня.
Дата без времени означает **конец дня** включительно.

### Расширить историю на новые таймфреймы

Ничего не делать: `load_bars(root, symbol, "1m", resample="4h")` соберёт
любой из `1m, 5m, 15m, 1h, 4h, 1d`.

### ⚠️ Обрыв соединения на ~17 КБ

Сеть на этой машине **рвёт соединение после ≈17 КБ** независимо от размера
файла. Файлы меньше 17 КБ проходят целиком, всё что больше — застревает на
112 секунд вместо 16.

**Решение уже встроено:** `ingest.py` качает **чанковыми Range-запросами**
по 16 КБ в 8 соединений параллельно. Не «упрощайте» это обратно в один
`requests.get` — вернётся та же проблема.

Проверка скорости: `1m`-файл должен качаться за **~11 секунд**, не за 112.

### Стоимость загрузки

≈11 с на 1m-файл месяца. 25 символов × 48 месяцев ≈ **3.5 часа**.

### Проверка после загрузки

## 8. Валидация: что означают гейты

Вердикт бинарный: `alive: true/false` + причины. Четыре гейта:

| Гейт | Порог | Что проверяет |
|---|---|---|
| Число сделок | ≥ 100 | достаточно ли данных для статистики |
| **DSR** | > 0.95 | Sharpe с поправкой **на число попыток** |
| **p-value** | < 0.05 | permutation-тест: сигнал связан с доходностью? |
| PBO | < 0.5 | переносится ли выбор параметров на новые данные |

### ⚠️ Гейты применимы не всегда

**Для дельта-нейтральных книг** (`net ≡ 0`) замерено:
- `min_trades` **неприменим** — направленных сделок нет;
- permutation-тест **вырожден** — p ≡ 1.0 при любом доходе книги, потому что
  доход стратегии в тест не входит.

В этом случае вердикт говорит **«НЕ ВЫНЕСЕН»**, а не «МЕРТВА». `alive` не
выносится. Обойти гейт нельзя: механизм срабатывает только при нулевой
экспозиции. **Не подкручивайте пороги** под желаемый ответ.

### Что вердикт НЕ видит

Слепые зоны (spec 8.2) — они едут в `verdict.warnings` и в дашборд:
ликвидация ноги перпа, риск биржи, депег стейблкоина, стоимость займа,
базис спот-перп на входе и выходе. Для плечевой дельта-нейтральной книги
**некоторые из них — доминирующий риск**, и числа их не отражают.

### ⚠️ Статистика не ловит подглядывание в будущее

Доказано (spec 8.1): две гипотезы — «сигнал посчитан по информации до `t`» и
«сигнал посчитан из самой доходности» — дают **одинаковое распределение**.
Никакой статистикой по выборке их не различить.

**Работает только проверка причинности:** `generate(bars[:k])` обязана
побитово совпасть с `generate(bars)[:k]`. Она вызывается в рабочем пути CLI
и в harness. Новая стратегия обязана её проходить.

## 9. Архитектурные инварианты — не нарушать

1. **`src/alpha_lab/validation/` не импортирует `strategies/`.** Валидатор
   слеп. Есть статический тест. Нарушение = подкрутка под стратегию.
2. **Сдвиг позиций на бар.** `held[t] = positions[t-1]`. Это то, что
   структурно исключает look-ahead. Не «упрощать».
3. **Издержки от `gross`, funding от `carry`, P&L от `net`.** Три раздельные
   величины двухногой позиции.
4. **Разрывы данных сегментируют ряд.** Стратегия перезапускается, состояние
   не переносится через пропуск.
5. **Пороги гейтов хранятся построчно** в хранилище (схема 2.0) — воронка
   судит прогон по тем порогам, с которыми он сделан.

## 10. Как добавить стратегию

```python
# src/alpha_lab/strategies/my_strategy.py
class MyStrategy:
    name = "my_strategy"
    history_bars = 20          # сколько хвостовых баров нужно решению

    def generate(self, bars: pd.DataFrame) -> pd.Series:
        """Целевая позиция -1..+1. Только информация по бар t включительно."""
        return pd.Series(0.0, index=bars.index)
```

Зарегистрировать в `build_strategy` (`strategies/base.py`), добавить имя
параметров в `PARAM_NAMES`, написать тест причинности. Для двухногой
позиции — `generate_legs(bars) -> PositionLegs(net, gross, carry)`.

**Индексная конвенция:** результат обязан иметь индекс, совпадающий с
`bars.index`. Движок потребляет позиции позиционно и проверит только длину,
но harness отвергнет несовпадение.

| Гипотеза | Результат |

**Вывод:** премия в funding реальна, но она **свойство конкретного актива**,

**Куда смотреть дальше:** структурные механические премии (funding-арбитраж
без тайминга, базис, каскады ликвидаций) — это требует **новых данных**
(стакан L2, поток ликвидаций), а не новых прогонов на этих.

## 12. Правила работы над кодом

- **TDD.** Сначала падающий тест, потом реализация.
- **Коммит после каждой задачи** с осмысленным сообщением.
- Полный набор под `-W error` остаётся зелёным.
- **Якорь:** одиночный прогон BTCUSDT `mr_base` 1h 2022–2025 остаётся
  `МЕРТВА` с неизменными метриками. Если он изменился — что-то сломано.
- **Тесты не ходят в сеть.** Фикстуры в `tmp_path`.
- Заметили, что тест утверждает неверное — **чинить тест**, но сначала
  доказать расчётом, что неверен именно он. Никогда не ослаблять допуск,
  чтобы «прошло».

### Известные ловушки, уже стоившие времени

| Ловушка | Как выглядит |
|---|---|
| Затравка ATR | Pine `ta.rma` сеет **средним первых len TR**, не первым TR. Разные затравки → разные стопы |
| `std(ddof=0)` vs `ddof=1` | Pine `ta.stdev` выборочный. Модель использует генеральный |
| Сдвиг на единицу при разборе позиций | Модель ставит `pos[бар_выхода]=0`, серия кончается **за бар до** выхода |
| Строковое выражение через `+` | Pine читает перенос как незакрытый литерал (CE10017 → CE10016) |
| `freq="1m"` в pandas 3 | Означает конец месяца, не минуту |
